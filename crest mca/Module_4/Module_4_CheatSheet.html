AI Security Practitioner: Context, Memory & Sensitive Data Exposure

SECTION 1: RISK CONCEPTS
🧠 Context manipulation — shaping what enters the model's context window to influence output
💾 Memory risk — persisted history can resurface or leak unexpectedly
👥 Cross-user exposure — one user's data leaking into another's session
SECTION 2: SENSITIVE DATA TYPES
🪪 PII
🔑 Credentials & secrets
🏢 Internal business data
SECTION 3: TESTING WORKFLOW
1️⃣ Test for context leakage across turns
2️⃣ Check cross-user/session isolation
3️⃣ Review responses for sensitive data
4️⃣ Recommend controls
SECTION 4: MITIGATION CONTROLS
ControlPurpose
Session isolationPrevent cross-user context bleed
Access control at retrievalEnforce authorisation before context assembly
Data minimisationReduce what could be exposed if leaked
SECTION 5: MULTI-TENANT RISK
Shared infrastructure must strictly isolate each tenant's context and memory
Access control must apply at the context/retrieval layer, not only the UI
SECTION 6: RESPONSIBLE PRACTICE
✅ Use synthetic test accounts
✅ Never expose real customer data during testing
✅ Trace exactly how leaked data reached the context
✅ Recommend layered isolation and minimisation controls
