AI Security Practitioner: RAG, Vector Store & Retrieval Security

SECTION 1: RAG ARCHITECTURE
🔍 Query → Retrieval → Context Injection → Generation
🧮 Vector database — stores documents as embeddings for similarity search
📐 Embeddings — numerical representations used to match query to content
SECTION 2: CORE RISKS
☠️ Retrieval poisoning
🔓 Unauthorised document retrieval
🏢 Cross-tenant data retrieval
📄 Sensitive document exposure
SECTION 3: TESTING WORKFLOW
1️⃣ Map the retrieval trust boundary
2️⃣ Craft queries to test unauthorised retrieval
3️⃣ Check cross-tenant segmentation
4️⃣ Recommend access-aware filtering
SECTION 4: RETRIEVAL POISONING vs UNAUTHORISED RETRIEVAL
RiskDescription
Retrieval poisoningAttacker plants crafted content into the knowledge base to be retrieved and trusted
Unauthorised retrievalA query surfaces documents the requester was never authorised to see
SECTION 5: ACCESS CONTROL IN RAG
Enforce access control at the retrieval layer, filtering candidate documents before they reach model context
Classify and tag sensitive documents at ingestion time
SECTION 6: RESPONSIBLE PRACTICE
✅ Use synthetic documents and test accounts
✅ Test only within agreed scope
✅ Never exfiltrate real sensitive documents
✅ Recommend secure segmentation controls
