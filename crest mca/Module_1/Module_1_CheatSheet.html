AI Security Practitioner: AI & LLM Security Foundations

SECTION 1: CORE TERMINOLOGY
🧠 AI — systems performing tasks that normally require human cognition
📈 ML — subset of AI that learns patterns from data instead of explicit rules
✍️ Generative AI / LLM — models that generate novel text, code, or media from learned patterns
Key distinction: LLM behaviour is probabilistic, not deterministic
A system prompt is advisory guidance to the model — not an enforced security control
SECTION 2: LLM ARCHITECTURE
👤 User — free-text prompts and queries
🧩 Application layer — orchestration, guardrails, session state
🤖 LLM — system prompt, context window, inference
🔌 Tools/APIs — plugins, agents, backend services
SECTION 3: MODEL LIFECYCLE
1️⃣ Data collection
2️⃣ Training
3️⃣ Evaluation
4️⃣ Deployment
5️⃣ Monitoring & update
SECTION 4: AI RISK vs TRADITIONAL RISK
CategoryTraditionalAI-Enabled
InjectionSQL/command injectionPrompt injection, instruction override
Data exposureDatabase leakageContext/memory/training data leakage
IntegrityCode tamperingData poisoning, model drift
Access controlBroken authorisationCross-user context bleed, retrieval overreach
SECTION 5: TRUST BOUNDARY MAP
🔓 Untrusted: user input, retrieved docs, tool output
🚧 Boundary: prompt assembly, context injection, tool parsing
🔒 Trusted: system instructions, validated app logic
Trust boundary = where data crosses from lower to higher trust
SECTION 6: ATTACK SURFACES & PRACTICE
✅ Prompt/instruction interface
✅ Context and memory handling
✅ Tool, plugin, agent invocation
✅ Training/update pipeline
