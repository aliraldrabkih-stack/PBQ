AI Security Practitioner: Third-Party, Tool & Agent Security

SECTION 1: CORE CONCEPTS
🔧 Tool use — the model calls a discrete function to act or retrieve data
📞 Function calling — the mechanism: structured call → execution → result returned
🤖 Agentic workflow — autonomous planning and chaining of multiple tool calls
SECTION 2: KEY RISKS
🔌 Plugin/connector supply chain exposure
🔓 Unsafe (over-broad) permissions
⚙️ Tool and API action abuse
🔗 Compounding risk across chained agent steps
SECTION 3: TESTING WORKFLOW
1️⃣ Review each connected tool/plugin's trust level
2️⃣ Attempt unintended agent action chains within scope
3️⃣ Compare granted permissions to actual need
4️⃣ Recommend least-privilege scoping
SECTION 4: ZERO TRUST FOR AI INTEGRATIONS
PrincipleApplication
Never implicit trustA tool call is not trusted just because it came from the model
Verify every actionCheck against least-privilege policy every time, not once
SECTION 5: LABS
Malicious Third-Party Integration — existing, medium
AI Agent Tool Abuse — proposed, hard
SECTION 6: RESPONSIBLE PRACTICE
✅ Test only within agreed scope
✅ Use synthetic accounts and sandboxed tools
✅ Never trigger real destructive third-party actions
✅ Recommend least-privilege permission scoping
